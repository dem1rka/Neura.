# Neura — пространство наблюдения

Рабочий frontend-прототип для Pizza Pitch. Основной язык интерфейса — русский. МРТ-просмотрщик из `demir` встроен в `/mri` и запускается вместе с остальными страницами Neura. Сервер и внешние API отсутствуют; приложение не диагностирует РАС и не рассчитывает риск.

## Запуск

Нужны Node.js 20.19+ и npm. Откройте терминал в этой папке (`AI sana/neura`):

```sh
npm ci
npm run dev
```

Откройте адрес, показанный Vite (обычно http://127.0.0.1:5173).

МРТ доступно по http://127.0.0.1:5173/mri. Все необходимые runtime-библиотеки включены в `package.json` и `package-lock.json` Neura. Отдельный запуск `demir`, Next.js или Docker не требуется. Docker-конфигурация Neura не создаётся.

Для телефона в той же Wi-Fi-сети запустите `npm run dev:lan` и откройте адрес **Network**, который покажет Vite, добавив `/mri`. `127.0.0.1` на телефоне указывает на сам телефон. Если порт 5173 занят, Vite выберет следующий доступный. На опубликованном сайте демо также работает без отдельного сервера: файл включается в `dist/demo/`.

```sh
npm run typecheck
npm test
npm run build
```

Готовая статическая сборка появляется в `dist/`. Для размещения настройте SPA fallback: неизвестные пути должны отдавать `index.html`. Не открывайте `index.html` напрямую через `file://`.

## Что работает

- `/` — продуктовая страница с переходами к модулям.
- `/dashboard` — показатели, график с переключением периода, фильтр событий, быстрые действия.
- `/game` — 8 ситуаций, четыре варианта ответа, изменение выбора, повтор инструкции, время, прогресс и завершение.
- `/game/report` — пять областей наблюдения, таблица событий, график времени, печать / сохранение PDF средствами браузера.
- `/questionnaire` — две авторские анкеты RU/KK/EN, каталог методик, JSON/CSV, объяснимые правила и мок-метрики.
- `/questionnaire/teacher` — прежние 10 вопросов педагога; сохранённые ответы доступны как раньше.
- `/questionnaire/report` — распределение ответов по категориям, полные ответы, темы для обсуждения, печать.
- `/mri` — настоящий просмотр `.nii` и `.nii.gz` через Niivue: Axial, Sagittal, Coronal, MPR, 3D; слайдеры X/Y/Z, яркость, контраст, цветовые схемы, метаданные NIfTI и CSV ABIDE.
- `/about` — миссия, ограничения, план развития и предполагаемые технологии.

В игре повтор инструкции показывает её текст снова; аудио не используется. Время включает ожидание на открытом шаге. Это метрика взаимодействия с интерфейсом, а не характеристика ребёнка. Игра не ограничена таймером: 10–15 минут — ориентир для обсуждения с взрослым.

## Данные и приватность

Все исходные записи на дашборде вымышлены и помечены. График активности — отдельный иллюстративный набор, а не статистика пользователя. Дашборд учитывает завершённую локальную игру, завершённую анкету и успешные открытия МРТ. История МРТ ограничена 20 событиями. Старые симуляции сохраняются в истории с прежней пометкой и не входят в счётчик просмотров.

`localStorage` хранит одну последнюю игру, текущий игровой выбор, одну прежнюю анкету педагога и историю событий МРТ под префиксом `neura.v1.`. Новая игра / прежняя анкета заменяет предыдущую. Новые анкеты сохраняются отдельно в `neura.v1.screening`: до 100 наблюдений по уникальным кодам. Эти записи учитываются в обзоре и доступны через ссылки в событиях. Они не синхронизируются между телефоном и ПК; для переноса используйте экспорт/импорт. Для МРТ сохраняются только случайный ID события, время, источник `local` / `example` и `simulated: false`; имя файла, его содержимое, SUB_ID и CSV не сохраняются. Данные сохраняются только для текущего браузера и origin. Для сброса демонстрации удалите ключи с этим префиксом в инструментах разработчика браузера. Для презентации используйте только вымышленные наблюдения.

МРТ-модуль читает, распаковывает и отображает реальные локальные NIfTI-файлы. Niivue работает через WebGL2, Papa Parse разбирает CSV в браузере. Выбранные файлы не отправляются на сервер. Файлы и фенотипический индекс хранятся только в памяти страницы и освобождаются при уходе с `/mri` или перезагрузке; для повторного просмотра их нужно выбрать заново. Повторное переключение между уже открытыми файлами не создаёт дубликатов событий в текущем сеансе. Неудачное чтение не записывается как просмотр.

## Работа с МРТ

Новый модуль анкет описан в конце этого файла.

1. Нажмите **Открыть демо**, чтобы посмотреть встроенный `mprage.nii.gz` без своего файла. Это предоставленный для демонстрации MPRAGE-том 128 × 256 × 256, сжатый без потерь с 16 МБ до 3,3 МБ. Он загружается только по нажатию, поддерживает все режимы и настройки. Для своих снимков нажмите **Добавить МРТ** или перетащите `.nii` / `.nii.gz` в панель **Исследования**.
2. Переключайтесь между файлами и режимами **Axial**, **Sagittal**, **Coronal**, **MPR**, **3D**. Колесо меняет срез, левая кнопка ставит перекрестие, правая с перетаскиванием меняет окно интенсивности. В 3D перетаскивание вращает объём.
3. Слайдеры X/Y/Z синхронизированы с перекрестием. Панель **Визуализация** управляет яркостью, контрастом и цветовой схемой; **Метаданные** показывает размеры, шаг вокселей и единицы из заголовка, ориентацию, тип данных и affine 4×4.
4. При необходимости импортируйте `Phenotypic_V1_0b_preprocessed.csv` или CSV с полем `SUB_ID`. ID извлекается из последней последовательности минимум пяти цифр в имени снимка. Его можно изменить вручную без повторной загрузки тома. Ведущие нули и суффикс `.0` нормализуются при сопоставлении.
5. Группа (`DX_GROUP`: 1 → ASD, 2 → Control), пол (`SEX`: 1 → мужской, 2 → женский), возраст (`AGE_AT_SCAN` / `AGE`) и центр (`SITE_ID` / `SITE`) берутся только из CSV. Это исходные данные набора, а не вывод модели.

На телефоне просмотрщик расположен перед панелями импорта. Коснитесь среза для установки перекрестия, меняйте X/Y/Z ползунками и вращайте 3D-объём пальцем. Кнопка демо прокручивает страницу к снимку. Повторное нажатие выбирает уже загруженный пример без повторного скачивания. В истории он отмечается как просмотр демо (`source: "example"`, `simulated: false`). Демо не содержит выдуманных фенотипических данных; CSV можно добавить отдельно.

Встроенный файл находится в `public/demo/mprage.nii.gz`. Его размеры и SHA-256 исходного NIfTI записаны в `src/features/mri/demo-manifest.json`; тест проверяет, что распаковка восстанавливает исходные байты. Исходный файл пользователя не изменён.

Нужен браузер с WebGL2 и достаточной памятью для распакованного тома. При ошибке запуска проверьте аппаратное ускорение. При ошибке чтения проверьте сам NIfTI-файл, а не только его расширение. Модуль предназначен для исследовательского просмотра; автоматическая диагностика, классификация и медицинские заключения не выполняются.

## Архитектура

```text
src/
  components/       общие элементы, оригинальная SVG-сцена
  data/             бренд, игровые истории, вопросы, демо-активность
  features/game/    игра и отчёт
  features/questionnaire/ анкета и отчёт
  features/screening/ новые анкеты, правила, JSON/CSV, мок-метрики
  features/mri/     просмотрщик Niivue, NIfTI/CSV, локальные стили
  layouts/          оболочка платформы и навигация
  pages/            главная, дашборд, о проекте
  services/         типизированный локальный сервис и подсчёт событий
  styles/           дизайн-система, адаптивность, печать
  types/            интерфейсы данных
```

Стек: React, TypeScript, Vite, Tailwind CSS, React Router, Framer Motion, Lucide React, Recharts, Niivue 0.69, Papa Parse. Страница МРТ и Niivue загружаются динамически, только при открытии модуля. Компоненты Next.js и отдельный провайдер темы из `demir` заменены общей оболочкой Neura. Шрифт использует локальный Inter при наличии и системные Segoe UI / Arial, без сетевой загрузки.

Для переименования измените `brand` в `src/data/content.ts`, а также title/description в `index.html` и статические упоминания в текстах. Для будущего NestJS REST API замените реализацию `src/services/storage.ts` асинхронным адаптером и обработкой состояний загрузки / ошибок в потребителях. Интерфейсы данных отделены от UI. Текущий прототип намеренно не включает сервер, аккаунты или медицинские модели.

## Демонстрация на питче

1. Откройте главную и перейдите на платформу.
2. Покажите три модуля и вымышленные показатели.
3. Пройдите игру; измените один ответ и повторите инструкцию, затем откройте отчёт.
4. Заполните анкету и покажите описательную сводку.
5. В МРТ-модуле нажмите **Открыть демо**, покажите срезы, 3D и настройки на встроенном снимке. При необходимости отдельно покажите импорт собственного NIfTI или CSV.
6. Завершите дорожной картой на странице проекта.

Прототип не является клиническим инструментом. Авторские вопросы не валидированы. Модель МРТ не обучена и не тестировалась. Проценты в разделе анкет относятся только к вымышленному демонстрационному набору, клиническая точность неизвестна. Вероятности РАС у ребёнка и диагностические выводы не представлены.

## Языки и оформление

В верхней панели доступны русский, казахский и английский языки, а также светлая и тёмная темы. Настройки сохраняются в браузере отдельно от наблюдений (`neura.preferences.v1`) и синхронизируются между вкладками. Смена языка не сбрасывает ответы игры и анкеты; сохранённые отчёты отображаются на выбранном языке. Печать использует светлый фон независимо от темы.

Переводы находятся в `src/i18n/translations.json`. Русская строка служит ключом, `en` и `kk` — её переводы. Для новых текстов используйте `useT()`, для динамических значений — параметры `{0}`, `{1}`. Игровые сценарии и вопросы локализуются через `getContent(t)` без изменения идентификаторов данных. Цвета тем и адаптивные переключатели находятся в `src/styles/preferences.css`.

Переводы нового модуля анкет хранятся рядом с ним в `src/features/screening/content.ts` и `Screening.tsx` как типизированные тройки RU/KK/EN.

Проверки локализации и настроек: `tests/i18n.test.ts`. Общая команда: `npm test`.

## Проверка интеграции МРТ

`npm test` проверяет локальное хранение, переводы, фильтрацию файлов, нормализацию SUB_ID и метаданные. `npm run test:e2e` запускает браузерные сценарии с автоматически созданными синтетическими NIfTI/CSV: загрузка `.nii` и `.nii.gz`, режимы и слайдеры, CSV, повреждённые файлы, удаление во время загрузки, навигация, темы, языки и мобильная ширина. Отдельные мобильные сценарии открывают встроенный MPRAGE без выбора файла, проверяют сенсорные ползунки и вращение 3D, повторное открытие и восстановление после ошибки сети. Скриншоты записываются в игнорируемый `test-results/`.

По умолчанию E2E использует установленный Microsoft Edge в Windows и Chromium в других ОС. Для Chrome задайте `PLAYWRIGHT_CHANNEL=chrome`; для браузера Playwright выполните `npx playwright install chromium` и задайте `PLAYWRIGHT_CHANNEL=chromium`. Тестовый сервер Vite запускается автоматически. `npm run preview` позволяет проверить `dist/` после `npm run build`. Для E2E поверх production-сборки задайте `PLAYWRIGHT_PREVIEW=1`.

## Анкеты и мини-экспертная система

На `/questionnaire` доступны **«Общение и поведение»** (8 вопросов) и **«Самочувствие и повседневная жизнь»** (10 вопросов) на русском, казахском и английском. Это независимо составленные авторские наблюдения, а не копии известных тестов. Анкеты и переводы не прошли клиническую валидацию и не имеют возрастных норм. Период наблюдения — последние две недели. Значения 0–3 описывают частоту трудностей; `null` означает «не знаю / не применимо».

**Открыть демо** показывает восемь вымышленных заполненных профилей. **Новое наблюдение** позволяет заполнить одну или обе анкеты. **Сохранить и разобрать** сохраняет ответы; **Дополнить ответы** обновляет выбранную запись. Отчёт поддерживает JSON/CSV и печать / PDF средствами браузера. Сохранённые недемонстрационные наблюдения учитываются в обзоре платформы.

Каталог содержит M-CHAT-R/F, AQ-10 Child, CAST и материалы о наблюдении за развитием. Защищённые тексты тестов не перепечатываются; можно перейти к оригиналам и перенести уже подсчитанный результат. Приложение не проверяет правильность исходного подсчёта. Условия использования и алгоритмы проверены 16.10.2026:

- [M-CHAT: условия](https://www.mchatscreen.com/mchat-rf/), [подсчёт](https://www.mchatscreen.com/mchat-rf/scoring/), [русский и казахский бланки в каталоге переводов](https://www.mchatscreen.com/mchat-rf/translations/). Для распространения электронной анкеты в ПО требуется лицензия авторов.
- [AQ-10 Child](https://docs.autismresearchcentre.com/tests/AQ10-Child.pdf), [условия ARC](https://www.autismresearchcentre.com/research/tests/), [CAST](https://www.autismresearchcentre.com/tests/childhood-autism-spectrum-test-cast/). ARC ограничивает коммерческое использование и изменения без разрешения.
- [CDC: скрининг и оценка](https://www.cdc.gov/autism/diagnosis/index.html), [возраст M-CHAT 16–30 месяцев в учебных материалах CDC](https://www.cdc.gov/ncbddd/actearly/autism/curriculum/documents/screening-autism_508.pdf).

Наличие перевода на сайте автора не подтверждает отдельную валидацию языковой версии. Поддерживаемый диапазон M-CHAT в этой версии — 16–30 месяцев. При 3–7 баллах без Follow-Up выводится «нужно интервью». AQ-10 Child интерпретируется только для 4–11 лет при подтверждении отсутствия интеллектуальных нарушений согласно условию оригинального бланка. За пределами условий автоматическая интерпретация отключена. Разные инструменты выводятся отдельно; баллы не суммируются.

Сопутствующие области: общение, гибкость, сенсорная нагрузка, сон, внимание, тревога, повседневные навыки. Демонстрационное правило «обсудить» срабатывает при среднем ответе ≥ 2 в полностью заполненной области. Это не клинический порог. Пропуски не считаются нулями; утрата навыков отмечается отдельно независимо от баллов. Диагнозы РАС, СДВГ и других состояний не вычисляются.

**Мок-метрики:** 3 TP, 3 TN, 1 FP, 1 FN; accuracy 75%. Сравнивается достижение порога направления по внесённым M-CHAT/AQ-10 с заранее заданной вымышленной меткой РАС. Это смешанный искусственный набор, не исследование точности методик. Метки заданы независимо от расчёта правил; ML-модели нет. Чувствительность, специфичность и precision вычисляются отдельно. Импортированные записи не входят в метрики. Клиническая accuracy и индивидуальная вероятность РАС неизвестны.

### Обмен файлами

**Бланк JSON / CSV** скачивает шаблон, **Мок-данные JSON / CSV** — заполненные примеры. Ограничения: 1 МБ, 1–100 записей в файле, максимум 100 в хранилище. Пакет целиком проверяется перед записью; дубликаты кодов не перезаписываются. JSON содержит справочные локализованные тексты в `questionnaires`; правила используют встроенные идентификаторы. Загрузка собственных определений методик и OCR PDF/фотографий не поддерживаются.

```json
{
  "schemaVersion": 1,
  "records": [{
    "schemaVersion": 1,
    "id": "CHILD-001",
    "ageMonths": 24,
    "language": "ru",
    "demo": false,
    "date": "2026-10-16",
    "regression": null,
    "answers": { "soc1": 2, "soc2": null },
    "mchat": { "total": 4, "followUp": 2 }
  }]
}
```

Все показанные поля записи обязательны, кроме `mchat`. Допустимо также `aq10: { "total": 6, "noLearningDisability": true }`. `noLearningDisability` и `regression` принимают `true`, `false`, `null`. Возраст — целые месяцы 0–215. Код — 1–40 латинских букв, цифр, дефисов/подчёркиваний, без ФИО. Для нового наблюдения того же ребёнка используйте отдельный код, например `CHILD-001-V2`.

CSV: одна строка — одно наблюдение; первые шесть столбцов обязательны. Заголовки: `id,ageMonths,language,demo,date,regression,mchatTotal,mchatFollowUp,aq10Total,aq10NoLearningDisability,soc1,soc2,soc3,soc4,flex1,flex2,flex3,flex4,sens1,sens2,sleep1,sleep2,att1,att2,anx1,anx2,day1,day2`. Неизвестные ответы — пустые ячейки; логические значения — `true`/`false` либо пусто для nullable-полей. Follow-Up допустим только для M-CHAT 3–7 и не выше первичного балла. Неизвестные поля и недопустимые значения отклоняются.

`tests/screening.test.ts` проверяет правила, границы, метрики, пропуски и обмен файлами. `tests/e2e/screening.e2e.ts` проверяет заполнение, импорт/экспорт, сохранение, источники, языки и сенсорный экран.
